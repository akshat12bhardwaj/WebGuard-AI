# Decisions

| ID | Decision | Alternatives | Reason |
| --- | --- | --- | --- |
| D1 | Repository in `website-risk-analyzer/` inside the course folder | Use the course folder itself | Keeps the handout PDF and personal documents out of the public repo |
| D2 | Shared extractor at `ml/feature_extraction.py` (manual had `backend/app/features.py`) | Keep manual path | Requested layout for this phase; backend imports it, so one definition remains |
| D3 | Virtual environment at `%USERPROFILE%\.venvs\wra`, outside OneDrive | `.venv` in repo | Avoids OneDrive syncing ~1 GB of packages |
| D4 | Model uses hostname only; scheme, path, `www.` and all 54 precomputed PhiUSIIL columns excluded | Use precomputed columns | Audit: 7 columns alone give ROC-AUC ≥ 0.95 (`URLSimilarityIndex` 0.996); all legitimate URLs are https `www.` homepages |
| D5 | Exclude `is_shared_hosting`, `is_ip`, `has_punycode`, `num_special_chars` from the model (still computed) | Keep them | First three never occur for a legitimate training host (label proxies); last is constant. Rules handle them in phase 2 |
| D6 | Group splits by eTLD+1 from the ICANN section of the Public Suffix List (so all `*.web.app` hosts form one group) | Include private suffixes (each `x.web.app` its own group) | Stricter: one attacker's sibling subdomains cannot appear in both train and test. Cost: big groups (web.app 5,754 rows) make split shares 72.5/14.1/13.4% instead of 70/15/15 |
| D7 | Split validation by domain into val_cal (calibrator fit) and val_thr (calibrator comparison + thresholds) | Calibrate and choose thresholds on all of validation | Avoids choosing thresholds on the calibrator's own fit data; test untouched |
| D8 | Selection metric: validation PR-AUC | Accuracy, F1 | Positive class is minority (35% in val); ranking quality matters more than one threshold |
| D9 | Thresholds: alert = lowest with FPR ≤ 10%; high = lowest with precision ≥ 95% (val_thr) | Fixed 0.5; max-F1 | Matches the manual's two-level warning design; bounds false alarms explicitly |
| D10 | Modest tuning: 8 random candidates, GroupKFold(3) by domain, LightGBM and XGBoost only | Large grid | Course scope; LR and RF kept at sensible defaults as baselines |
| D11 | Calibration kept only if it lowers val_thr Brier by ≥ 1e-4 | Always calibrate | Isotonic lowered Brier 0.1267 → 0.1239 and ECE 0.048 → 0.009, so kept |
| D12 | Candidate models saved with `joblib` compress=3 | Uncompressed | Random Forest shrank from 439 MB to 93 MB |
| D13 | Unicode hostnames converted to punycode with the stdlib IDNA codec (IDNA 2003) | `idna` package (IDNA 2008) | No extra dependency; differences only affect rare characters |
| D14 | Registered-domain-only ablation trained as a diagnostic, not a candidate | None | Quantifies how much the model relies on subdomain structure, a known collection artifact |
| D15 | No EDA notebook | `notebooks/eda.ipynb` | Scripts + figures are reproducible; avoids duplicate analysis |

## Phase 3 — EXP-03 design and promotion criteria (written 2026-10-15, BEFORE any EXP-03 result existed)

| ID | Decision |
| --- | --- |
| D26 | **Data source:** observed hostnames with a subdomain from the already-downloaded Tranco list Q2Y54 (subdomains on, created 2026-10-14), ranks 100,001–1,000,000 only (the external test used ranks <= 100,000). No hostnames are generated. Label = legitimate (0) by assumption: popularity is supporting evidence, not proof. |
| D27 | **Exclusions:** invalid or IP hosts; hosts without a subdomain; shared-hosting suffixes (anyone can publish); registered domains present in PhiUSIIL val/test, the external test set, any Kaggle binary host, the OpenPhish snapshot, or PhiUSIIL train with any phishing row; hosts already in PhiUSIIL. At most 3 hosts per registered domain (infrastructure domains such as office.net would otherwise dominate). Remaining hosts split by registered domain 70/15/15 (seed 42) into new_train / new_val / new_test. |
| D28 | **Candidates:** A = unchanged baseline. B = PhiUSIIL train + all of new_train. C = PhiUSIIL train + 5,000 random new_train hosts (dose check). Same XGBoost hyperparameters as the baseline (no re-tuning), scale_pos_weight recomputed. Calibration and thresholds exactly as phase 1 (isotonic; val split by domain into val_cal/val_thr; alert = lowest threshold with FPR <= 10%, high = lowest with precision >= 95%) but on PhiUSIIL val + new_val. |
| D29 | **Promotion criteria** (each candidate at its own validation-chosen thresholds; all must hold): (1) Tranco-subdomain FPR at alert and at high each <= 50% of the baseline's (baseline 0.9347 / 0.8613); (2) OpenPhish recall at alert and at high each >= baseline − 0.10 (baseline 0.8688 / 0.8507); (3) Tranco-apex FPR at high <= baseline + 0.02 (baseline 0.0437); (4) PhiUSIIL test PR-AUC >= baseline − 0.03 (baseline 0.7356); (5) PhiUSIIL test Brier <= baseline + 0.01 (baseline 0.1412). If B and C both pass, choose the one with the lower FPR on new_val legitimate hosts at alert (validation data, not external). If neither passes, keep the baseline. External sets are used once for this go/no-go and never to tune thresholds. |
| D30 | **Promotion mechanism:** the baseline file `models/model_bundle.joblib` is never overwritten. A promoted candidate is selected through `models/production.json` (path to its bundle); without that file the baseline is used. |

## Phase 3 — results and follow-up decisions (2026-10-16)

| ID | Decision | Reason |
| --- | --- | --- |
| D31 | EXP-03 data also excludes hosts that are themselves public suffixes (`rr.gov.br`, `k12.az.us`): 831 hosts. Deviation from D27, found by the integrity test before any promotion decision; both runs failed D29 the same way. `registered_domain()` keeps its 'last two labels' fallback for such hosts (marked `shortcut:`), because fixing it would regroup 30 PhiUSIIL hosts and change the frozen baseline split | Such hosts are not one owner's site; the fallback mis-grouped them as `gov.br` |
| D32 | **EXP-03 outcome: baseline retained.** B and C both fail D29 (OpenPhish recall and PhiUSIIL Brier; B also PR-AUC). No `models/production.json` was created | Pre-registered rule |
| D33 | Threshold comparisons use exact probabilities everywhere: `ml.predict` no longer rounds; fusion picks the category from probability vs stored thresholds (levels) and places the integer risk score inside that level's band. Baseline thresholds unchanged | API flagged more hosts than the evaluation (Tranco-subdomain 94.8% vs 93.5%) because rounding moved tied isotonic scores across thresholds. Now identical (93.47%) |
| D34 | New candidates store unrounded thresholds (`pick_thresholds(..., ndigits=None)`); the baseline's rounded ones are kept | Rounding to 4 decimals can cross a tied isotonic step (B's 'high' fell to 92.9% precision). Baseline's alert 0.3662 is the exact 0.366171 rounded *up*: validation FPR 6.9% instead of up to 10% (stricter than the rule; recorded, not changed) |
| D35 | Fusion guard unchanged (cap model below 'high'). Option `guard_cap="below_alert"` implemented and measured but **not adopted** | Offline measurement: legit subdomain hosts at caution+ 93.5% → 5.1%, but OpenPhish caution+ 87.3% → 9.5%. Choosing between them is a product decision for the user, not something to tune on the external set |
| D36 | Proposal (not applied): `BRAND_IN_HOST_MISMATCH` fires on 154/3,000 legit Tranco subdomain hosts (brand-owned CDN names such as `*.microsoft.com.edgekey.net`, the `.google` TLD) vs 4/221 OpenPhish hosts. Options: downgrade to medium, or an allowlist of brand-owned CDN suffixes and brand TLDs. Must be validated on data other than the external test set | Changing it now would tune a rule on test data |

## Phase 4 — scoring hardening and threat intelligence (2026-10-16)

| ID | Decision | Reason |
| --- | --- | --- |
| D37 | D35 confirmed: the guard stays at 'below_high' (default of `fuse`); 'below_alert' is not used | Below-alert dropped OpenPhish detection to 9.5% (phase 3) |
| D38 | Brand rules rewritten (D36): tokens are matched whole (no prefixes); public-suffix tokens are ignored (`blog.google`); **high** `BRAND_IN_HOST_MISMATCH` = brand in the registrant-chosen name, or brand in a subdomain together with login words; new **medium** `BRAND_IN_SUBDOMAIN` = brand in a subdomain only (CDN naming such as `<name>.microsoft.com.edgekey.net`, but also a phishing trick); `BRAND_IN_PATH` unchanged. Brand-owned exceptions limited to cited Microsoft 365 domains | No blanket CDN exemption: Azure Traffic Manager names (and similar) are user-chosen, so exempting providers would let phishing through. Designed from documented conventions + synthetic fixtures, not tuned on the external set |
| D39 | New code uses `site_domain()` (PSL-aware; a public-suffix, IP or unknown-suffix host returns itself). The frozen `registered_domain()` stays for baseline reproduction | Fixing the frozen function would regroup 30 PhiUSIIL hosts |
| D40 | Google Safe Browsing via the v4 Lookup API (`threatMatches:find`), key from `GOOGLE_SAFE_BROWSING_KEY` as a query parameter; HTTP 429 = rate_limited; 400/401/403 = error; empty object = no_match | v4 documented with no deprecation notice; v5 `urls:search` is `v5alpha1` (checked 2026-10-16) |
| D41 | Local OpenPhish lookup = newest `feed_<UTC>.txt` across `data/feeds/openphish/` (refreshed by `python -m backend.openphish_update`, at most every 12 h) and the frozen `data/raw/openphish/`. Exact normalised URL = match; same host, other URL = unverified; snapshot older than 24 h (`OPENPHISH_STALE_HOURS`) = unverified | A listing in an old snapshot may be offline or cleaned; the frozen evaluation snapshot is never modified |
| D42 | Responses carry `api_version` "1.0"; contract in docs/API_CONTRACT.md | Lets the extension detect breaking changes |

## Phase 6 — evaluation protocol (2026-10-16)

| ID | Decision | Reason |
| --- | --- | --- |
| D48 | Phase 6 claims rest only on fresh held-out data collected after a recorded freeze (`docs/PHASE6_PROTOCOL.md` v1.0 DRAFT; `reports/phase6/frozen_system.json` once frozen). The earlier external set is diagnostic | It was used for EXP-02/EXP-03 decisions, the bias analysis and the brand-rule redesign |
| D49 | Fresh OpenPhish items are stored as `scheme://host/path` (userinfo, query and fragment dropped) plus the raw-feed SHA-256; the raw feed is not stored | Phishing query strings can hold victims' e-mail addresses or tokens; OpenPhish forbids redistribution |
| D50 | Collector guards: refuses before the freeze or after any frozen file changes; ≥ 12 h between snapshots; skips a repeated feed commit; 10-day window (≤ 20 snapshots); Tranco only after the window, from a list created after it; never overwrites (exclusive create) | Prevents tuning, duplicate data and overwrites. Window length is flag F2, awaiting approval |
| D51 | Open flags F1–F6 (protocol section 9) must be decided before `freeze` | Measured on pre-freeze data: prior-domain exclusion keeps only 65/263 new phishing hosts (shared platforms removed, F1); ~1,122 legit subdomain hosts available vs 2,000 planned (F3) |
| D52 | Flags decided by the user (2026-10-16), protocol v1.0 final text (not frozen): F1 primary group keeps the prior-registered-domain exclusion, plus a supplementary group of new hosts on listed shared-hosting platforms (no criterion) and a disclosed limitation; F2 10-day window, ≤ 20 snapshots, never extended; F3 all eligible legitimate subdomain hosts, actual n reported, no duplication; F4 E2 deferred ("not run"); F5 E3 lists the enabled sources; F6 raw-model and final-API metrics reported separately, final high risk = high_risk + dangerous.
