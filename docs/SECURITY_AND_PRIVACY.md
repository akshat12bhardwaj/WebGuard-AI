# Security and privacy

Mandatory extension permissions are `activeTab`, `storage`, `scripting` and loopback host `http://127.0.0.1:8000/*`. There is no permanent content script or all-sites grant. Manual toolbar checks inject once into Chrome's isolated top frame using temporary activeTab access. Opt-in automatic mode requests `tabs` and `notifications`, checks addresses only, and removes optional permissions when disabled. Notification deduplication, lifetime and navigation ownership remain guarded.

DOM extraction reads structure: password-field counts/visibility/ownership, form action origin/scheme/method, aggregate link/frame/resource origins, title characteristics and meta-refresh origins/delays. It never reads typed values, passwords, cookies, authorization headers, raw HTML, arbitrary page text or script bodies. Title text is used locally to derive characteristics and is not transmitted. Structural destinations omit paths, queries and fragments. Closed shadow roots and cross-origin/nested frame contents are not inspected. [DOM schema](DOM_FEATURE_SCHEMA.md) documents exact traversal, array, payload and time bounds.

Document identity and navigation epochs are checked around extraction and display. Structural cache keys include the tab/document/fingerprint. Missing, denied, timed-out or incompatible inspection remains explicit, never a fabricated all-zero success. The backend rejects extra fields, malformed aggregates and oversized bodies before analysis.

The chosen URL goes to the local backend and applicable reputation services; query strings may be necessary for exact matching. The extension removes fragments and hides query values in displayed addresses. Diagnostic exports retain original URLs/evidence and should be handled accordingly. Structural evidence goes only to the local backend: `Analyzer.collect` receives the URL alone. Private/local hosts are skipped for third-party lookup. The backend does not fetch the target website.

PhishTank, URLhaus, Google Safe Browsing and local OpenPhish have separate statuses. Only confirmed `match` yields dangerous; `unverified` is not confirmed. Errors, rate limits and missing keys mean unavailable. No listing is never proof of safety; stale local listings are unverified. Keys stay in local environment variables and must not appear in logs or commits. Joblib objects can execute code: load only the trusted locally trained URL bundle.

Hostname ML has dataset artifacts and substantial subdomain bias; calibration is not a real-world safety guarantee. DOM rules provide structural warnings, not validated phishing classification. Snapshots cannot establish JavaScript submission behavior or later page changes. CORS restricts origins but is not authentication; keep this unauthenticated development server on loopback. Native Windows toasts and the actual optional-permission consent dialog require manual verification.
